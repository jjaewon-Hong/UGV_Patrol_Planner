기록

    이 데모는 무엇으로 도는가

    제어기의 핵심 다섯 유닛은 ROS 2에 의존하지 않는 C++17 라이브러리(ugv_core)입니다. 그 코드를 한 줄도 고치지 않고 WebAssembly로 컴파일했고, ROS 2에서 센서·배터리·구동부를 대신하던 시뮬레이션 노드 세 개는 같은 규칙의 C++ 루프로 옮겼습니다. 화면(JavaScript)은 그리기와 입력 전달만 합니다.

    ugv_core — 기존 코드 그대로 U1 지형과 경사 비용 · U2 A* · U3 순찰 순서 · U4 복귀 에너지 · U5 임무 상태 기계
    브라우저에서 실제로 도는 것ROS 2에서만 도는 것

    가장 오래 안 간 지점부터 도는 순찰 순서Python 제어기 (C++와 같은 경로를 냄)
    장애물 발견 시 재계획, 배터리 복귀 판단RViz2 화면 (여기서는 3D 탭이 대신함)
    명령 해석과 잘못된 입력 경보정사영상에서 장애물을 찾는 딥러닝 추론 (여기서는 그 결과 지도를 사용)

    웹용 시뮬레이션 루프는 ROS 2 시나리오 시험과 같은 조건으로 시험합니다. 캠퍼스 순찰은 ROS 2 실행과 똑같이 이동 319회, 최대 경사 13.5°가 나와야 통과합니다(네이티브 빌드와 WebAssembly 빌드 모두).

    검증 결과

    단위 시험Python 82개, C++(GoogleTest) 36개 통과. push마다 GitHub Actions에서 실행
    시나리오 시험 (실제 ROS 2 실행)S1 정상 순찰, S2 장애물, S3 배터리 부족, S4 비정상 입력, S5 캠퍼스 순찰. Python·C++ 제어기 모두 통과
    캠퍼스 순찰깃발 3개 모두 방문, 장애물 진입 0회, 이동 중 최대 경사 13.5° (한계 15°)
    재계획 시간요구 0.5초 이내. 실측 Python 48 ms, C++ 8 ms
    C++ vs Python A*600개 경로가 칸 단위로 같음. C++가 약 20배 빠름 (평균 0.2 ms)
    장애물 인식직접 만든 정답 기준 건물+나무 IoU 0.63 (목표 0.6)

    구현 과정

    1. 설계 먼저. 요구사항(기능 22개, 비기능 8개)과 유닛 5개를 문서로 정한 뒤 Python으로 구현하고 합성 지형에서 시험했습니다.
    2. 캠퍼스 지도 만들기. 국토지리정보원 정사영상(25 cm)에서 DeepLabV3로 건물·나무·물을 찾아 10 m 격자로 줄였습니다.
    3. 정답 데이터 직접 만들기. OpenStreetMap에는 가로수와 일부 건물이 빠져 있어, 라벨링 도구를 만들어 캠퍼스 중앙을 직접 칠해 평가했습니다.
    4. 실제 고도와 등판 한계. Copernicus GLO-30 고도를 10 m 칸으로 보간했습니다. 30°로는 막히는 곳이 없어 소형 바퀴형 UGV 기준인 15°로 정했습니다. 위 슬라이더로 직접 바꿔 볼 수 있습니다.
    5. C++ 포팅. 유닛과 제어기 노드를 C++17로 옮기고, Python과 경로가 칸 단위로 같은지 확인했습니다.
    6. 웹 데모. 같은 C++ 코드를 WebAssembly로 빌드해 이 페이지를 만들었습니다.
