# 웹 데모 계획: 브라우저에서 바로 돌려 보는 UGV 순찰

면접관이 저장소를 내려받거나 ROS 2를 설치하지 않고, **링크 하나로** 이 프로젝트가 동작하는 모습을 보고 직접 만져 볼 수 있게 한다.

- 주소(예정): `https://jjaewon-hong.github.io/ugv_patrol_planner/`
- 방식: C++ 핵심(`cpp/` 의 `ugv_core`)을 WebAssembly로 컴파일 + HTML/CSS/JS 화면 + GitHub Pages 정적 배포. 서버 없음.
- 상태 (2026-11-13): 0~6단계 구현과 로컬 확인 완료. 7단계(GitHub Pages 켜기, push)와 8단계(README에 공개 주소)는 남아 있다. 12장에 진행 결과와 계획에서 달라진 점을 적었다.
- 로컬에서 보기: `bash scripts/setup_emsdk.sh`(처음 한 번) → `bash scripts/build_web.sh` → `bash scripts/serve_web.sh` → `http://localhost:8000`

## 1. 목표와 범위

**목표**

1. 30초 안에 "무엇을 만든 프로젝트인지" 보인다: 페이지를 열면 캠퍼스 지도에서 순찰이 자동으로 돌기 시작한다.
2. 버튼과 클릭으로 핵심 기능 다섯 가지를 직접 확인한다: 경로 계획, 순찰 순서, 장애물 재계획, 배터리 복귀, 비정상 입력 경보.
3. 웹 데모가 "그림만 흉내 낸 것"이 아니라 **시험을 통과한 바로 그 C++ 코드**로 돈다는 것을 보여 준다.

**하는 것**

- `ugv_core`(U1 지형, U2 A\*, U3 순찰 순서, U4 복귀 에너지, U5 임무 상태 기계)를 수정 없이 WASM으로 빌드
- ROS 2 시뮬레이터 세 개(구동, 배터리, 인식)와 같은 규칙의 시뮬레이션 루프
- 2D 지도 화면, 3D 지형 화면, 조작 패널, 상태·경보 패널
- 지도 3종: 캠퍼스(모델 지도), 캠퍼스(OSM 지도), 시험용 합성 지형
- push마다 자동 빌드·배포

**하지 않는 것 (브라우저에서 안 되는 것)**

| 안 하는 것 | 이유 | 대신 |
|---|---|---|
| ROS 2 노드, DDS 통신, RViz2 | 브라우저에서 못 돌림 | 같은 순서의 시뮬레이션 루프 + three.js 3D. ROS 2 실행 장면은 README 스크린샷 링크 |
| DeepLabV3 실시간 추론 | 모델·영상이 큼 | 이미 만든 장애물 격자 사용, 인식 결과 비교는 그림으로 |
| 정사영상 원본 배경 | 국토지리정보원 이용 조건 미확인 | 색칠한 장애물 지도만 사용 (9장 결정 사항 참고) |
| Python 제어기 | C++와 결과가 같음이 이미 검증됨 | "C++ = Python 600개 경로 일치" 결과만 표시 |

## 2. 전체 구조

```
┌─────────────────────────── 브라우저 ───────────────────────────┐
│  화면 (HTML/CSS/JS)                                            │
│   ├ 2D 지도 (Canvas)   ├ 3D 지형 (three.js)   ├ 조작·상태 패널 │
│   └──────────── app.js: 입력 → 명령, 매 틱 상태 읽기 ──────────│
│                          ▲ C 함수 호출 (JSON, 배열)            │
│  ugv_web.wasm ───────────┴─────────────────────────────────────│
│   ├ web_api.cpp   C 인터페이스 (얇은 껍데기)                   │
│   ├ sim.cpp       구동·배터리·인식 시뮬레이션 + 틱 루프  (신규)│
│   └ ugv_core      U1~U5 (기존 코드 그대로)                     │
│                                                                │
│  maps/*.json      지도·설정·시나리오 (빌드 때 .npy/.yaml에서 변환)│
└────────────────────────────────────────────────────────────────┘
        ▲ 정적 파일만 제공
   GitHub Pages  ◄── GitHub Actions: emsdk로 WASM 빌드 → 지도 변환 → 배포
```

**핵심 설계 결정**

1. **시뮬레이션도 C++로 쓴다.** 구동·배터리·인식 규칙을 JS가 아니라 `cpp/web/sim.cpp`에 둔다. 이유는 두 가지다. 배터리 소모가 U4의 `energy_step`과 같은 식이어야 하고, 같은 코드를 WASM 없이 **GoogleTest로 시험**할 수 있다. JS는 그리기와 입력만 맡는다.
2. **인터페이스는 평범한 C 함수 + JSON.** Embind 대신 `extern "C"` 함수 몇 개와 JSON 문자열로 주고받는다. 상태 JSON은 이미 있는 `status_json()`을 재사용한다.
3. **`ugv_core`는 건드리지 않는다.** 지도는 `.npy` 파일 대신 JS가 넘긴 배열로 `TerrainMap(n, elevation, params)` 생성자를 그대로 쓴다. 장애물은 `add_obstacles()`로 넣는다.
4. **번들러 없이 간다.** Vite/React 없이 ES 모듈 몇 개와 three.js 한 파일만 쓴다. 저장소에 Node 의존성이 생기지 않고, 면접에서 코드를 열어 보여 주기도 쉽다.

## 3. WASM 인터페이스 (`cpp/web/`)

**틱 한 번의 순서** (ROS 2 실행에서 메시지가 흐르는 순서와 같게)

1. 구동: 대기 중인 다음 칸이 이웃 칸이면 한 칸 이동 (`drive_sim.py`와 같은 규칙)
2. 배터리: 이동했으면 `energy_step`만큼 차감 (`battery_sim.py`)
3. 제어기에 배터리 전달 → `on_battery`
4. 제어기에 위치 전달 → `on_pose`
5. 인식: 새 위치의 센서 반경 안에 있는 숨은 장애물 보고 → `on_obstacles` (`perception_sim.py`). 인식은 위치를 받고 나서 보고하므로 위치 다음이다
6. 나온 출력 처리: `NextCell`은 구동의 다음 칸으로, `PathUpdate`·`Status`·`Alarm`은 화면용 상태에 기록

**C 함수** (`cpp/web/web_api.cpp`)

```c
// 세계 만들기: 지도 배열과 설정값 14개(칸 크기, 등판 한계, 에너지 계수, 기지, 시작 칸, 틱 간격 ...).
// 등판 한계를 바꾸면 다시 호출한다. 0이면 성공, 1이면 ugv_last_error()에 이유.
int   ugv_create(int n, const double* elev, const uint8_t* obstacles, const double* cfg);
const char* ugv_last_error(void);
void  ugv_set_hidden(const int* cells, int count);      // 시나리오의 숨은 장애물
void  ugv_command(const char* text);                     // "add r c" | "remove P1" | "start" | "stop"
void  ugv_report_obstacle(int r, int c);                 // 사용자가 클릭한 장애물 (인식 보고와 같은 경로)
void  ugv_set_battery(double wh);                        // 배터리 슬라이더
int   ugv_tick(int count);                               // count 틱 진행, 이동한 횟수를 돌려줌
const char* ugv_state_json(void);   // 위치, 배터리, 상태(status_json 그대로), 방문 수, 경로, 새 경보, 새 장애물, 재계획 횟수·시간
const char* ugv_plan_json(int r0, int c0, int r1, int c1);  // 경로 탐색기용: 경로, 비용, 오르막, 계획 시간(20회 평균)
const float* ugv_return_energy(void);                    // 복귀 에너지 지도 (히트맵 표시용)
int   ugv_traversable(int r0, int c0, int r1, int c1);   // 이웃 칸 이동 가능 여부 (막힌 이동 수 세기)
```

- 시간(`now`)은 벽시계가 아니라 **틱 수 × 틱 간격**인 시뮬레이션 시간을 쓴다. 속도를 바꿔도 순찰 순서가 같다.
- 잘못된 명령과 지도 밖 좌표는 기존 코드가 경보로 돌려준다(NFR-04). 웹에서 "잘못된 입력 보내기" 버튼으로 그대로 보여 준다.

## 4. 지도 데이터 변환 (`tools/export_web.py`)

빌드할 때 `.npy`와 `.yaml`을 지도별 JSON 하나로 바꾼다. 브라우저에서 npy/yaml 파서를 쓰지 않기 위해서다.

| 출력 | 입력 | 담는 것 |
|---|---|---|
| `maps/campus.json` | `config/campus.yaml`, `scenarios/campus.yaml`, `data/campus_pred/*` | 고도, 장애물, 장애물 종류, 칸 크기 10 m, 등판 한계 15°, 기지 (42, 30), 문 위치, 깃발 3개 |
| `maps/campus_osm.json` | `config/campus_osm.yaml`, `data/campus_osm/*` | 같은 구성, OSM 장애물 |
| `maps/default.json` | `config/params.yaml`, `scenarios/default.yaml`, `data/dem_100x100.npy` | 합성 지형, 숨은 장애물 16칸, 순찰 지점 3개 |

- **깃발은 변환할 때 미리 계산한다.** `place_flags`는 Python 난수(`random.Random(7)`)를 쓰므로, JS에서 다시 만들지 않고 결과 좌표를 JSON에 넣는다. ROS 2 실행과 같은 `(64, 21), (3, 1), (35, 48)`가 나온다.
- 고도는 반올림하지 **않는다**. 원본 `.npy`가 float64라서 float64 그대로 base64로 넣는다(경사 계산이 ROS 2 실행과 비트 단위로 같게). 지도 하나에 약 134 KB, 압축 전송하면 더 작다.
- 변환 결과는 저장소에 넣지 않고 빌드 때 만든다(`web/maps/`는 `.gitignore`).

## 5. 화면 설계

**페이지 구성 (한 페이지, 위에서 아래로)**

1. **머리말:** 프로젝트 이름, 한 줄 소개, GitHub 링크, CI 배지
2. **데모:** 지도 + 조작 패널 (아래 그림). 열자마자 캠퍼스 순찰이 자동 시작
3. **이 데모는 무엇으로 도는가:** 구조 그림 한 장과 "브라우저에서 도는 것 / ROS 2에서만 도는 것" 표
4. **검증 결과:** 시험 수, C++ = Python 경로 일치, 속도 20배, 인식 IoU 0.63 (README 표를 짧게)
5. **구현 과정:** README의 6단계 요약 + 직접 라벨 비교 그림 + ROS 2/RViz2 실행 스크린샷

**기능과 보여 주는 요구사항**

| 조작 | 일어나는 일 | 보여 주는 것 |
|---|---|---|
| 지도 선택 | 세계를 새로 만들고 그 지도의 기본 순찰 시작 | 실제 지역 지도(FR-20~22), 모델 지도와 OSM 지도 차이 |
| 깃발 모드로 지도 클릭 | `add r c` 전송. 장애물 칸이면 경보 | 순찰 지점 등록(FR-07), 잘못된 지점 경보 |
| 깃발 클릭해 삭제 | `remove Pn` | 지점 삭제(FR-09) |
| 장애물 모드로 클릭·드래그 | 인식 보고로 전달 → 경로가 막히면 즉시 재계획, 걸린 시간 표시 | 재계획 0.5초 이내(NFR-01), 경로 없음 처리 |
| 배터리 슬라이더를 낮춤 | 복귀 에너지보다 부족해지는 순간 기지로 복귀 | 배터리 복귀(FR-13·14, NFR-03) |
| "복귀 에너지 보기" 켜기 | 칸마다 기지까지 필요한 에너지를 색으로 표시 | U4의 역방향 Dijkstra |
| 등판 한계 슬라이더 | 세계를 다시 만들어 경로가 바뀜, 막힌 이동 수 표시 | 경사 판단(FR-03·04), 30°→15° 결정 근거 |
| 경로 탐색 모드: 두 칸 클릭 | 순찰과 별개로 A\* 경로·비용·계획 시간 표시 | A\* 자체(FR-05·06), 속도 |
| 잘못된 명령 보내기 | `go`, `add 999 999`, 지도 밖 장애물 전송 | 멈추지 않고 경보(NFR-04) |
| 속도 1×/5×/20× | 프레임당 틱 수 변경 | - |
| 2D/3D, 높이 과장 | 같은 상태를 3D 지형으로 | RViz2 화면 대체 |

**시각 표현**

- 색은 README·RViz2와 같게: 건물 빨강, 나무 초록, 물 하늘색, 경로 파랑, UGV 자홍, 기지 하늘색 네모, 문 회색 아치, 고도는 회색 음영.
- 2D는 Canvas 한 장(100×100칸 × 6~8 px). 지형 바탕은 한 번만 그려 두고 경로·UGV·깃발만 매 프레임 다시 그린다.
- 3D는 three.js 높이 격자(101×101 정점) + 장애물 상자 인스턴스. 궤도 카메라(드래그 회전, 휠 확대).
- 다크·라이트 모두 지원, 폭 900 px 아래에서는 패널이 지도 아래로 내려간다. 모바일에서는 2D만 기본.
- WASM을 못 쓰는 브라우저에서는 데모 자리에 실행 스크린샷과 안내 문구를 보여 준다.

## 7. 단계별 진행

각 단계는 끝났을 때 확인할 기준이 있고, 앞 단계가 통과해야 다음으로 간다.

| 단계 | 내용 | 끝난 기준 |
|---|---|---|
| 0 | 준비: emsdk 설치(WSL), 빈 `ugv_core`를 WASM으로 빌드해 Node에서 A\* 한 번 호출 | `ugv_plan`과 같은 경로·비용이 Node에서 나옴 |
| 1 | `sim.cpp` 작성과 네이티브 시험 | `test_sim` 통과 (8장 기준). 기존 C++ 23개 시험도 그대로 통과 |
| 2 | `web_api.cpp` + WASM 빌드, `export_web.py` | Node 스크립트로 캠퍼스 시나리오를 끝까지 돌려 단계 1과 같은 결과 |

## 8. 검증 방법

**네이티브 시험 (`cpp/test/test_sim.cpp`, CI에 포함)**

ROS 2 시나리오 시험 S1~S5와 같은 조건을 시뮬레이션 루프로 돌려 같은 기준을 확인한다.

| 시나리오 | 확인 |
|---|---|
| S1 정상 순찰 | 세 지점 방문 횟수 차이 1 이하 |
| S2 장애물 | 숨은 장애물 16칸을 만나 재계획, 장애물 칸 진입 0회 |
| S3 배터리 부족 | 30 Wh로 시작해 복귀 완료, 기지 도착, 잔량 0 초과 |
| S4 비정상 입력 | 경보 5개 이상, 이후 정상 순찰 |
| S5 캠퍼스 | 깃발 3개 모두 방문, 장애물 진입 0회, **이동 319회, 최대 경사 13.5°** (ROS 2 실행과 같은 값) |

- S5의 이동 횟수와 최대 경사는 경로만으로 정해지므로 ROS 2 실행과 **같은 숫자**가 나와야 한다. 다르면 시뮬레이션 루프가 틀린 것이다.
- 배터리 최저 잔량처럼 메시지 도착 순서에 따라 달라지는 값(ROS 2에서도 2.98~3.28 Wh로 흔들림)은 숫자 일치가 아니라 조건(0 초과)으로 확인한다.

**WASM 시험 (CI에 포함)**

- Node에서 `ugv_web.wasm`을 불러 S5를 돌리고 네이티브와 같은 결과인지 확인한다. 컴파일러가 달라도 결과가 같다는 확인이다.
- `export_web.py` 단위 시험: 깃발 좌표가 `scenario_points`와 같은지, 배열 크기와 설정값이 원본과 같은지.

**화면 확인 (수동 + 스크린샷)**

- 단계마다 로컬 서버를 띄워 브라우저에서 확인하고, 5장 표의 조작을 하나씩 눌러 본다.
- 배포 후 공개 주소에서 다시 한 번 전체를 확인한다(캐시 없는 새 창, 모바일 폭).

**계획에서 달라진 점**

- **틱 순서:** 장애물 보고를 위치 보고 **뒤**로 옮겼다. 처음 계획대로 장애물을 먼저 전달하니 제어기가 한 칸 전 위치에서 재계획해 멈췄다(S1·S2 시험이 잡아냄). ROS 2에서도 인식 노드는 위치를 받고 나서 보고한다.
- **설정 전달:** `ugv_create`의 설정을 JSON 문자열 대신 숫자 배열로 받는다. C++ 쪽에 JSON 파서를 두지 않기 위해서다.
- **컴파일러 경고:** Emscripten(clang)이 `energy.cpp`의 람다 캡처 한 줄을 C++20 확장으로 경고했다. `ugv_core` 소스는 그대로 두고 웹 빌드에서만 그 경고(`-Wno-c++20-extensions`)를 껐다.
- **방전 처리 추가:** 배터리가 0이면 구동이 멈추고 경보를 낸다(슬라이더로 0을 만들 수 있어서 넣음). 스스로 방전되는 일은 없어야 하며 S3 시험이 확인한다.
- **"한 번 눌러 보기" 버튼 추가:** 경로 앞에 장애물 놓기, 배터리를 부족하게, 잘못된 명령 보내기. 면접관이 클릭 한 번으로 핵심 기능을 보게 하려는 것이다.
- **아직 모르는 장애물 표시:** 시험용 지형의 숨은 장애물을 점선으로 보여 준다(ROS 2 화면에는 없음). 제어기가 발견하면 주황색으로 바뀐다.
- **`controls.js` 없음:** 조작 코드가 작아 `app.js`에 합쳤다. 3D의 궤도 카메라도 직접 써서 three.js는 한 파일만 쓴다.
- **3D는 보기 전용:** 깃발과 장애물은 2D에서 놓는다.
